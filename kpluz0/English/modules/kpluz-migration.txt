
Purpose: Single reference for a fresh chat to continue migrating the KPluz modules from legacy inline PHP to the modern container.php + scorer.php + q-engine.php architecture. Supersedes both prior hand-over documents and incorporates every rule established through Module 33 in this session.

1. Project Context
System: KPluz academic excellence platform (PHP + MySQL, legacy code from ~2012).
Goal: Migrate ~500 Math modules from inline procedural PHP (in math/modules/*.php) to the modern template architecture.
Already complete: q-engine.php (procedural + static modes), scorer.php (writes to test_results), container.php (modern layout). All rules below are proven across 33 converted modules.

Non-goals: MCQ subject modules (English, Science) — those go through q-display-legacy.php, a different loader. Do not touch.

10. Grade Progression (§E — Consolidated)
The legacy tier system (0-8) is deprecated. Replace with grade-keyed $configs table:

Shape 1 — simple ranges:

$configs = [
    0 => ['Easy' => [min, max, ...], 'Hard' => [min, max, ...]],
    1 => [...],

Shape 2 — option pools:

    0 => ['Easy' => [[count, min, max]], 'Hard' => [[count, min, max], [count, min, max]]],

Calibration: For most arithmetic modules, Hard(grade N) = legacy Medium(grade N). Legacy Hard was calibrated too high. For graded-threshold modules (add/subt with distinct Easy/Hard pools), preserve real differentiation.

13. Distractor Generation — CRITICAL RULES
13.1 No Outliers (Band Rule)
Every distractor must be numerically close to the correct answer. Raw operands ($num1, $num2), trivially-far values (percentage itself, num ± perc), or structurally-obvious wrong operations are excluded by a tight band filter:

php
$band = max(FLOOR, abs($ans) * PCT);
// PCT = 0.10 (percentage), 0.15 (arithmetic/geometry), 0.20 (business)
// FLOOR = 2 (percentage), 0.5–1 (arithmetic/distance), 0.1 (volume)
Filter pattern: build a candidate pool → filter by abs($c - $ans) <= $band → take first 3 unique.

Example failure this fixes: "Kirby bought 2900 dolls, gave 21% away, how many left?" — old choices were 2291, 21, 2879, 2921. 21 is 2270 away from the answer, trivially eliminable. New choices with 10% band: 2233, 2262, 2291, 2320 — all plausible "used wrong percentage" answers.

Modules fixed: word-percentage, word-percentage-business, word-dec-mult-div, word-dec-add-subt, word-circle, word-temperature, word-volume, alg-eval-exp.

13.2 Successive Powers-of-Ten (Metric Conversions)
For metric conversion modules (conv-length, conv-volume, conv-weight), the four choices must be consecutive powers of ten with the same significand. This targets the decimal-shift misconception directly:

php
function split_sig_exp($v) { /* extract [sigStr, exp] with no trailing zeros */ }
function make_metric_distractors($correct, $n = 3) {
    [$sig, $p] = split_sig_exp($correct);
    $o = rand(0, $n);           // random offset so correct isn't always lowest/highest
    $s = $p - $o;
    $choices = [];
    for ($i = 0; $i <= $n; $i++) {
        $choices[$i] = fmt_num((float)$sig * pow(10, $s + $i));
    }
    return distractors; // omit the slot at offset $o
}
Correct = 5000 with o=0 → {5000, 50000, 500000, 5000000}. Same set with o=2 → {50, 500, 5000, 50000}.

English (non-metric) conversions stay as wrong-factor distractors (×2, ×3, ×4, ×0.5, ×0.25) — English factors (12, 3, 5280, 16) are not powers of ten.

13.3 Shuffle-Slice Bug (NEVER DO THIS)
Anti-pattern:

php
$allChoices = array_merge([$answer], $extra);   // correct + many
shuffle($allChoices);
$allChoices = array_slice($allChoices, 0, 4);   // ← drops correct ~50% of the time
Fix:

php
$distractors = array_slice($extra, 0, 3);       // build 3 FIRST
$allChoices = array_merge([$answer], $distractors); // append correct
shuffle($allChoices);                            // shuffle once
This bug existed in sci-notation (early version) — correct answer was silently dropped for "Express 406" and similar.

13.4 Fraction Distractors
All distractors reduced via gcd() + cross-multiply dedupe against the correct answer. Candidate mutations: numer±1/denom, numer/denom±1, sums-of-numerators over sums-of-denominators, swapped, off-by-two. Used in: word-fractions-mult-div.

13.5 Algebraic Expression Distractors
For expression/equation modules (alg-exp, alg-add-subt-like-exp), use mutate_alg_exp — change one number per candidate (coefficient, constant, or exponent), or flip one operator. All structurally similar to the correct answer.

13.6 Structural Distractor Types
Category	Technique
Arithmetic	Combine operands, ±1/±10, ±5%/-10% of answer
Percentage	perc±1..5 used instead of perc; ±5%/±10% shifts
Business	+tax, −tax, base+rate vs base+rate×(sales−quota)
Circle	15% band; wrong-operation candidates filtered in-band
Volume	15% band; structurally-wrong candidates dropped if far
Algebraic	mutate_alg_exp one-number-per-candidate

15. Rendering <sup> and HTML-Bearing Choices
render_choices htmlspecialchars choice text — a choice of "3.45 x 10<sup>-3</sup>" would render as literal <sup>-3</sup>. Bypass with manual rendering:

php
<?php
$plainLens = [];
foreach ($q['choices'] as $c) $plainLens[] = strlen(strip_tags($c));
$maxLen = max($plainLens);
$choiceWidthEm = round(0.62 * $maxLen + 3.2, 2);
?>
<div class="alg-grid-2x2">   <!-- or alg-flex / alg-grid-1col -->
    <?php foreach ($q['choices'] as $c): ?>
        <a href="?ansclick=<?php echo urlencode($c); ?>"
           class="alg-choice"
           style="width:<?php echo $choiceWidthEm; ?>em;">
            <?php echo $c; ?>
        </a>
    <?php endforeach; ?>
</div>
strlen(strip_tags($c)) gives the visual length (excludes <sup>/</sup> chars), so the button is correctly sized.

Trusted-display pattern (for <sup> modules)
php
// On ansclick:
$clickedDisplay = htmlspecialchars($clicked);
foreach ($cur['choices'] as $c) {
    if ($c === $clicked) { $clickedDisplay = $c; break; }  // trusted HTML
}
If the click matches a server-generated choice, show the HTML. If not (URL tampering), htmlspecialchars fallback escapes it. No XSS surface.

Modules using manual rendering
sci-notation, alg-exp-eq, alg-exp, alg-add-subt-like-exp.

16. Encoding Rules
Never render raw × or ÷ glyphs — they display as ? in windows-1252 contexts.

Symbol	Replacement	In which fields
× (multiplication)	x (ASCII letter)	All displayed math
÷ (division)	&divide; (HTML entity)	All displayed math
^-3 (exponent)	<sup>-3</sup>	All displayed math (but bypass render_choices)
₱ (peso)	P prefix or drop entirely	Currency problems (plain P in prompt text, plain numbers in choices)
+ in URL	urlencode() (never +→[ hack)	All ansclick URLs
Legacy +→[ hack (used in alg-exp-eq): replaced with urlencode(). Clicking 3a+5b used to arrive as 3a 5b (space) and always score wrong.

19. Retry Loops — Safety Rule
Every while or do-while in generation must have a finite attempt counter:

php
$safety = 0;
do {
    // generate
    $safety++;
} while (condition && $safety < N);   // N in 20-100
Applies to: repeat prevention, constraint satisfaction (min-difference), trend forcing, image validation.

20. Repeat Prevention
Pattern 1 — Value history (last2 / lastNum / used):

php
$last = $_SESSION[$sessionKey]['lastNum'] ?? 0;
$tries = 0;
do {
    $n = rand($min, $max);
    $tries++;
} while ($n == $last && $tries < 20);
$_SESSION[$sessionKey]['lastNum'] = $n;
For static banks (pie-charts, etc.): $_SESSION[$sessionKey]['used'] array of indices. Reset at exhaustion.

Pattern 2 — Trend constraint (trends): for sequence modules. Max 3 consecutive same-direction. Change the 3 in all four places to adjust.

30. Standard "New Question" / "Submit" Flow
For all bypass modules:

php
if (isset($_GET['ansclick']) && isset($_SESSION[$sessionKey]['current']) && !isset($_POST['Submit2'])) {
    // 1. Read $cur = current question state
    // 2. $clicked = (string)$_GET['ansclick']
    // 3. $scorer->processAnswer($clicked, $cur['answer'], $cur['lvl'])
    // 4. $result = ['correct', 'clicked', 'cur']
    // 5. unset($_SESSION[$sessionKey]['current'])   ← AT ANSWER TIME
}

if ($result === null || isset($_POST['Submit2'])) {
    // generate new question, store in session, $q = current
}

render_header(...);
// HTML: $result !== null ? show-feedback : show-question
// Form: Submit2 always (Subsubmit1 only if FIB pattern, not for MCQ)
Two rules that trip people up:

if ($result === null || isset($_POST['Submit2'])) — the || is essential

unset($_SESSION[$sessionKey]['current']) — must be at answer time, not generation time

31. Verification Checklist (10-point)
Load without error — no PHP warnings, no 500 errors

Auth works — logged-out redirects to login

First question renders — image loads, prompt shows, choices appear

Correct answer — score increments, feedback shows correct

Wrong answer — score does not increment, feedback shows correct answer

Difficulty switch (if applicable) — Easy ↔ Hard changes behavior

No repeats — 10× New Question produces 10 distinct questions

DB write — test_results row has correct module_id, qnum incremented

Console debug — if $scorer->outputConsoleDebug() is called, verify Resolved module ID: <expected>

Visual match — layout matches reference modules (no broken CSS)

Additional checks per-category:

Band-distractor modules: verify all 4 choices are numerically close to the answer (no outlier)

<sup> modules: verify <sup> renders (not literal tags)

Prose modules: verify 1-per-row layout when choices are long

Metric-conversion modules: verify choices are consecutive powers of ten with random offset
